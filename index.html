SYSTEM OVERVIEW

How TruthGuard works

Unlike basic RAG, TruthGuard checks whether the retrieved answer can be trusted.

Verification lifecycle

Five steps from question to explainable decision

1
Retriever agentSearches the document corpus using keyword and semantic relevance; returns passages with source metadata.
2
Synthesizer agentDrafts a candidate answer from the retrieved passages and records which claims need evidence.
3
Critic / adversaryActively looks for contradictory values, outdated versions, supersession clues and unsupported assertions.
4
Resolution engineEvaluates authority, applicability/scope, effective date and explicit supersession. If evidence is insufficient, it refuses to guess.
5
Verified answerShows the decision, supporting evidence, conflicting evidence, provenance and uncertainty in plain language.

Trust principles

What makes the system different

Authority + Scope + Date

Newest does not automatically mean correct. A newer memo with limited scope cannot silently override an official policy for everyone.

Side-by-side conflict diff

Show both positions, their dates, scope and authority so a reviewer can inspect the disagreement.

Safe resolution

When the corpus cannot establish which rule applies, surface the conflict and explicitly say what evidence is missing.

Honest prototype boundary

This MVP is an interactive front-end simulation with seeded demo logic. Production-grade semantic retrieval, LLM agents, authentication and database persistence require backend integration.
